# Phase 6 exit-criteria smoke

Walks the project's Phase 6 deliverables (G-code preview pipeline:
slice → parse → IR → render → stats; drag-drop loader for raw
`.gcode` + Bambu `.gcode.3mf`) end-to-end on a clean checkout.
Mirrors `phase-5-smoke.md` — half automated (Rust + frontend
tests), half human-driven (UX flow that needs a real GUI
session).

Phase 6's structural exit criterion is **slice → preview**:
clicking the Slice button on a real plate produces a preview the
user can scrub, recolor, hover, and inspect; dropping an external
`.gcode` or `.gcode.3mf` reaches the same preview surface. The
automated half pins the data-shape contracts as a Rust integration
test. The manual half walks the live UI so the toolbar, slider,
hover, color picker, and drop overlay are all exercised.

## Automated half — runs in CI

```
$ cargo test --workspace
$ npm test
```

What `phase6_smoke.rs` exercises:

1. **Slice from scene → preview pipeline.** Real
   `slic3r_ffi`-driven slice of `20mmbox-LF.stl` through PR-3-2's
   orchestrator. The output G-code feeds `build_preview` +
   `compute_layer_stats` + `compute_job_stats`. Asserts
   `layer_count > 0`, `bounding_box.max.z > 0`, non-zero
   extrusion segments.
2. **Color modes round-trip.** Each `ColorMode` (Feature, Speed,
   Flow, LayerTime, Tool) runs through `encode_colors`. Asserts
   every mode produces a non-empty buffer of the same length
   (per-mode buffers must match `extrusion_count * 6` floats).
3. **Stats consistency.** Per-layer stats count = job_stats
   `layer_count`. Sum of per-layer durations is within 5% of the
   job total — captures off-by-one regressions in the
   layer-aggregation loop.
4. **Foreign-slicer header compat.** Synthetic G-code with
   `; generated by …` lines for Orca / Prusa / Cura runs through
   the preview pipeline. PR-3-8's header parser correctly
   classifies each origin; the IR builds without errors.
5. **`.gcode.3mf` round-trip.** PR-3-10's writer produces a
   2-plate container with thumbnail + AMS bindings. PR-6-14's
   reader extracts both plates with metadata + thumbnail intact.
   The embedded G-code is preview-ready.
6. **Registry cleanup.** A loaded preview's handle resolves;
   after `drop`, it's gone.

What `phase6_smoke.rs` does NOT exercise — covered by the manual
half:

- **Drag-drop wiring.** Tauri's webview drag-drop event isn't
  reachable from an integration test (needs a live window).
  The routing logic (`handleDrop`) is unit-tested in
  `src/preview/__test__/DropZone.test.ts`; the UI overlay needs a
  human.
- **60fps scrub.** Frame-time gating needs a real WebGL context;
  cut in PR-6-16 per its cut-candidate note (Playwright nightly
  apparatus deferred). Verified subjectively in the manual half.
- **Auto-switch + cache.** `useSlicePreviewBridge` listens for
  `slice:plate_finished` events; only reachable from a Tauri
  runtime.

`preview_perf.rs` also runs as part of `cargo test --workspace`
— gates the FR-GP-9 budgets on a 5 MB synthetic fixture
(parse + IR build < 2 s, stats < 500 ms, color encode < 400 ms
per mode in debug; release-mode extrapolation comfortably under
the 50 MB / 5 s contract).

## Manual half — preview walkthrough

The flow below is the live-UI counterpart of the automated
fixture. Drive it on a clean checkout (`npm run tauri dev`) and
verify each step matches the expected outcome before moving on.

### 1. Build a scene + slice

1. Launch the app. Default scene shows the A1 mini bed +
   one plate. Click `+ New Plate` twice; three tabs total.
2. On Plate 1, load `external/OrcaSlicer/tests/data/test_stl/ASCII/20mmbox-LF.stl`
   via the file-open dialog. (Or any small STL.)
3. Click the topbar **Slice** button.
4. Wait for the slice panel to show `Finished` + a `.gcode`
   path. The app should **auto-switch to preview mode** — the
   workspace flips from the 3D scene to the preview canvas with
   the freshly-sliced G-code already mounted.

### 2. Color modes

The toolbar shows the color-mode picker (Feature / Speed / Flow /
Layer time / Tool). Click each in turn:

- **Feature**: walls vs infill vs supports show distinct colors.
- **Speed**: gradient from low (perimeters) to high (travel /
  infill).
- **Flow**: gradient by volumetric flow rate.
- **Layer time**: each layer's segments share a color; bright
  layers are fast, dim are slow.
- **Tool**: single color for a single-extruder print.

For each, the recolor is fast (sub-100ms): the buffer swap is a
single `swapExtrusionColors` call, geometry stays put.

### 3. Layer slider

The slider sits at the bottom of the canvas. Three modes:

- **Single** (`1` key): one thumb, only the chosen layer renders.
- **Up to** (`2` key): one thumb, layers `1..N` render with the
  depth-fade shader giving the top ~25 layers visual emphasis.
- **Range** (`3` key): two thumbs, layers `A..B` only.

Arrow keys step the layer; Shift+arrow steps 10. Home/End jump
to first/last.

**60fps spot-check.** Hold the arrow key in `up-to` mode on a
~200-layer print. The animation should stay smooth — no
jankiness; the shader uniform update + GPU cull is the hot path
and stays under frame budget.

### 4. Travel + retraction toggles

In the toolbar's visibility group, toggle **Travels** on. Gray
lines appear between extrusions. Toggle **Retractions** on. Red
dots appear at retraction points. Toggle both off — geometry
stays only.

### 5. Hover inspection

Hover the mouse over a printed segment. A tooltip appears with:

- Feature label (e.g., "External perimeter")
- Source G-code line (`G1 X… Y… E… F…`)
- Position (mm)
- Speed (mm/s)
- Layer + tool

Move to a different feature; the tooltip updates without flicker.

### 6. Drag-drop external `.gcode`

1. Open a file manager. Find any sliced `.gcode` file — your own
   recent slice (`/tmp/n3o-slice-*/plate_1.gcode`) works, as
   does anything OrcaSlicer / Bambu Studio / PrusaSlicer / Cura
   wrote.
2. Drag it onto the preview canvas. The dashed-border drop-zone
   overlay appears mid-drag.
3. Release. The preview reloads with the dropped file's
   geometry. Slicer-of-origin shows in the full-job panel
   (Orca / Prusa / Cura / etc.).

### 7. Drag-drop `.gcode.3mf`

If you have a Bambu Studio sliced `.gcode.3mf` (export → Send to
Printer → Save), drag it onto the preview canvas the same way.
Confirm:

- The preview renders plate 1's geometry.
- The full-job panel shows the **plate thumbnail PNG** above the
  time breakdown.
- For multi-plate `.gcode.3mf`, a **"Plate 1 of N" badge** sits
  near the panel title.
- If the file ships AMS bindings, the **AMS bindings row** lists
  them (`m1→slot 1, m2→slot 2, …`).

If you don't have a `.gcode.3mf` handy, the automated half pins
this contract — skip to step 8.

### 8. Plate switching

Switch back to scene mode (`P` key). Load + slice a different
model on Plate 2. Switch back to preview mode — Plate 2's slice
shows. Click Plate 1 in the tab strip — Plate 1's prior slice
re-mounts (cached). Plate 3 has no slice yet — the preview
shows an empty state ("Slice the active plate first").

### 9. Drop error path

Drag a non-`.gcode` file (a PNG, a text file, anything) onto the
preview canvas. Confirm the bottom-left toast reads
`only .gcode and .gcode.3mf files supported`. Dismiss with the
`×` button.

If any step's assertion fails, the offending pipeline link is
broken; trace through the layer named in the failure.

## Out of scope (deferred)

These were named in the original ticket but cut from MVP /
deferred:

- **Frame-time Playwright gate** — needs a WebGL-capable CI
  lane; cut per PR-6-16's own cut-candidate. Manual scrub-check
  in step 3 covers the contract until nightly infrastructure
  catches up.
- **Multi-plate plate-picker UI for `.gcode.3mf` drops** — MVP
  loads plate 1 + surfaces the badge. Picker deferred per
  PR-6-14's open question.
- **Real foreign-slicer fixtures checked in** — synthetic
  fixtures in `phase6_smoke.rs` exercise the header-detection
  contract. Real-printer-flavored fixtures are a Phase 6 follow-
  up; the test point is the slicer-of-origin classification + the
  preview pipeline's acceptance of each flavor, both pinned by
  the synthetic path.
- **WebGL memory profiling** — PR-6-16's own out-of-scope note.
  The Rust-side resident-memory budget isn't gated today; that's
  a follow-up.
